# Nexus API migration log

Every change to the API contract (`docs/API_CONTRACT.md`) gets one entry here. Backend and frontend are separate repos, so each entry is landed as **paired commits** on same-named branches; both commit messages cite the entry id.

| Id | Date | Finding | Endpoint(s) | Change | Backend | Frontend |
|---|---|---|---|---|---|---|
| ML-001 | 2026-11-11 | SEC-02 (contract M-14) | `GET /tournaments`, `GET /tournaments/:tournamentId` | `registeredTeams[]` items are trimmed to `{ _id, teamName, status }` unless the caller is an admin (optional cookie auth; the GETs stay public). Admin responses are unchanged. | `fix/security` — `fix(SEC-02)` | `fix/security` — test mocks follow the new shape. No source change: public pages read only `teamName`, `status` and the count; the admin screen already sends the cookie. |
| ML-002 | 2026-11-11 | SEC-03 (contract M-15) | `POST /bookings`, `PUT /bookings/:bookingId` | Request bodies are validated (400 + field message instead of 500). `totalAmount` from the client is ignored; the server stores `membersCount × hours × 100`. Stations must exist and be `Available` and are claimed atomically, else 409. Response shapes are unchanged. | `fix/security` — `fix(SEC-03)` | No change: the frontend still sends `totalAmount` (now display-only) and already shows `response.data.message`. |
| ML-003 | 2026-11-11 | SEC-04 | all routes with a body; `POST /users/login`, `POST /users/register` | Bodies with `$`-prefixed or dotted keys → 400 `"Invalid request."`. Login/register require string `email`/`password` (login with a missing password is 400, was 500). Success shapes unchanged. | `fix/security` — `fix(SEC-04)` | No change: the frontend never sends such bodies and already toasts `response.data.message`. |
| ML-004 | 2026-11-11 | SEC-05 | every POST / PUT / DELETE | Form-encoded and other non-JSON bodies are no longer accepted (415). A foreign `Origin` header is refused (403). Shapes unchanged. | `fix/security` — `fix(SEC-05)` | No change: axios sends JSON, and the browser sends the frontend's own origin, which is on the allow-list. |
| ML-005 | 2026-11-11 | SEC-06 | all `/api/*`; stricter on `POST /users/login`, `/users/register`, `/messages` | New 429 response in the standard error envelope when a per-IP limit is exceeded. | `fix/security` — `fix(SEC-06)` | No change: Login, Register and tournament/booking screens already toast `response.data.message`; Contact shows its existing fixed error alert. |
